# FRAME — паспорт продукта и архитектуры
Версия паспорта: 2.0.2
Дата: 10.08.2026

## 1. Назначение
FRAME — локальное мобильное PWA для строительного мастера. Оно должно быть быстрым рабочим инструментом на объекте, а не CRM/1С.

## 2. Золотые правила UX
1. Не захламлять экран кнопками, блоками и меню.
2. На экране показывать итог и самое важное; детализация открывается нажатием на показатель.
3. Если показан конкретный заказ, он кликабелен и ведёт в карточку заказа.
4. Цифра раскрывает, из чего она сложилась.
5. Длинный список — отдельный экран. Bottom-sheet используется только для коротких действий.
6. Назад должно быть доступно после прокрутки без возвращения к началу страницы.
7. Все формы сохраняют изменения только по явному «Сохранить» на редактируемых экранах.

## 3. Модель
Физический объект = место/адрес + заказчик.
Заказ = самостоятельная работа/этап бизнеса по этому адресу.
Один физический объект может содержать много независимых заказов: разные квартиры, повторные выезды, кухня после полов и т.д.
Главная сущность интерфейса и аналитики — заказ.

Связь:
Клиент/контакт → физический объект → заказы → работы / расходы / покупки / оплаты / фото / документы.

## 4. Статусы заказа
- Черновик
- Согласован
- В работе
- Ожидает оплаты
- Приостановлен
- Завершён
- Оплачен

«Активные» на главной: согласованные, в работе, ожидающие оплаты и приостановленные. Черновики не считаются активными.

## 5. Финансовая модель
Стоимость заказа = договорная стоимость работ.
Оплачено = фактические платежи.
Осталось = договорная стоимость - платежи.

Расходы, уменьшающие чистый доход:
- выплаты работнику;
- материалы, включённые в фиксированную цену «под ключ»;
- прочие расходы по заказу;
- общие расходы: бензин, инструмент, прочее;
- НПД.

Возмещаемые заказчиком покупки:
- показываются отдельно «К возмещению»;
- не уменьшают прибыль по работе;
- могут иметь фото чека.

НПД:
- настройка заказа 0 / 4 / 6%;
- начисляется на фактически полученные платежи;
- входит в расходы и уменьшает чистый доход.

Чистый доход месяца = фактически получено - невозмещаемые расходы - НПД.
Главная цель по умолчанию = 300 000 ₽ чистыми за календарный месяц; редактируется.

## 6. Даты
Заказ хранит дату создания/начала и дату завершения.
Каждый платёж хранит собственную дату.
Аналитика дохода относится к месяцу фактического поступления денег, а не к дате выполнения работ.

## 7. Документы
Есть общая картотека документов FRAME и документы конкретного заказа.
Фильтры: Все / КП / Перечни / Акты.
Документ можно удалить из истории без удаления заказа.
Любой документ связан с заказом и объектом.

## 8. Прайс-лист
Основной справочник должен содержать повторяемые рабочие направления.
Редкие разовые работы не засоряют прайс и добавляются в заказ вручную.
Будущее расширение: сантехника, электромонтаж, керамика, ГКЛ/перегородки, малярные работы, кухни/мебель и др.
Большой справочник добавляется отдельным data-релизом после стабилизации ядра.

## 9. Текущие реальные заказы
- Детейлинг «ПроЗащиту», 5-я Матросская 26: 23 000 ₽ работ; 7 651 ₽ к возмещению; ожидает оплаты.
- Веселковая 12Б, ООО «АТМОСФЕРА»: 74 000 ₽ фиксированная цена; 28 500 ₽ материалов внутри цены; НПД 6%; ожидает оплаты.
- Леонова 54: старый заказ по полу 33 362,50 ₽ оплачен; новый отдельный заказ «Сборка кухни» 40 000 ₽.

## 10. Хранилище и миграции
IndexedDB: FRAME_DB
DB_VERSION: 2
Текущий принцип: никаких destructive migration без отдельного явного решения.
Старые объекты, заказы, платежи и фото должны переживать обновления.

## 11. Текущий roadmap
- Полевой тест камеры iPhone.
- Дальнейшая полировка чистой навигации.
- Телефоны/контакты текущих заказчиков по мере появления данных.
- После стабилизации ядра: крупный пакет объектов и расширенный каталог расценок.
- Дальше: инженерные направления, кухни/мебель, при необходимости Telegram-интеграции.

## 12. Правило релиза
Каждое значимое обновление FRAME обновляет:
- код;
- этот паспорт;
- CHANGELOG;
- ROADMAP;
- TEST_REPORT.
